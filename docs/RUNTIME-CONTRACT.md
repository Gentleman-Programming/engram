# Pi HTTP runtime contract

`GET /runtime-contract` exposes a Go-owned **server handler contract** for the Pi
HTTP adapter. It is separate from the [MCP foundation](AGENT-CONTRACT.md): matching
names or digests do not establish TypeBox schema equivalence or general Pi parity.

## Authority and identity

`internal/server/runtime_contract.go` binds the advertised routes to their actual
handlers and preserves the existing route authentication wrappers. It generates
both the endpoint's stable projection and `plugin/pi/runtime-contract.json`.

The response contains `contract_id`, `revision`, `status`, `digest`, `operations`,
`supporting_routes`, and dynamic `instance_id`. The initial identifier is
`engram.pi-http-runtime/v1`, revision `1`, status `pi-http-server-contract`.
There are 22 Pi operations; `mem_suggest_topic_key` is explicitly `client-local`.
Composite operations enumerate their server bindings. Supporting routes account
for runtime session resolution, prompt capture decisions, and compaction context.
Client-side formatting and fallback algorithms are not certified by route presence.

The digest is SHA-256 over Go `encoding/json.Marshal` of the typed stable projection
with `digest` omitted. Struct field order is the declared Go order, string-keyed
maps use Go's JSON key order, and arrays retain their order. `instance_id` and the
release version are not hashed. This bounded format is not a general JSON-number
canonicalizer; adapters compare the complete generated expected projection rather
than copying the test-only MCP vector encoder or inferring compatibility from SemVer.
Changes to server contracts require deliberate declaration/version updates and
public handler/adapter regressions, not merely a new advertised status.

`/health` remains unchanged. Shared/local read-only metadata follows its existing
policy. Session-owned mode requires the existing bearer token for the entire
handler, including qualification; the endpoint does not introduce a new token.
An instance ID identifies the configured server/store, not remote attestation or
proof of local ownership. An advertised contract does not prove adapter business
semantics; qualification and lifecycle behavior require their own functional tests.

## Pi qualification

`gentle-engram` loads the bundled Go-generated projection and compares every stable
field, including the declared digest and operation bindings. Only an exact match
is supported initially: no older-contract allowance or SemVer fallback. The model
cannot supply the expected projection, digest, or transport authority.

Tools retain their existing registration, but readiness and memory/session effects
are gated by the runtime handshake. Metadata is rechecked before dispatch, including
observation recovery. Missing, malformed, unknown, or changed projections produce
upgrade/restart guidance rather than silently dispatching into a legacy server.
Startup safety policy still takes precedence over registration and effects.

Local `PATH`/`ENGRAM_BIN` startup retains its existing instance-ownership checks.
An explicit `ENGRAM_URL` skips only local binary ownership and auto-start: it still
requires an exact server contract and an instance identity. A changed bound server
identity blocks dispatch; restart Pi to bind a newly qualified runtime. Owned
transport qualification uses its private bearer token and readiness identity.

These checks are bounded adapter qualification, not remote attestation, general
JSON canonicalization, TypeBox/MCP schema equivalence, or proof of semantic parity.

## Generate and check

From the repository root, using UTF-8 stdout redirection:

```sh
go run ./tools/runtime-contract > plugin/pi/runtime-contract.json
go run ./tools/runtime-contract -check
```

`-check` compares exact generated bytes and never rewrites the file. A stale or
missing projection exits `1` with a diagnostic. Invalid arguments exit `2`;
`-help` describes the command. Generation opens no store and includes no dynamic
instance identity. The existing MCP generator and Foundation artifact are unchanged.
