# Pi agent tool projections

Pi's native inventory matches Go's `ProfileAgent`; input and output envelopes are not identical across transports. This audit records the current projections for issue #1348 and identifies unresolved capability gaps instead of claiming full semantic parity.

## Authority and scope

- Go's MCP definitions in `internal/mcp/mcp.go` and HTTP handlers in `internal/server` own the contracts and agent/admin boundary. Pi schemas and dispatch are projections; the registration regression compares the public native inventory against the current Go profile rather than freezing a second list.
- `mem_delete`, `mem_stats`, `mem_timeline`, and `mem_merge_projects` require deliberate administrative access, such as a separate `engram mcp --tools=admin` client. Pi does not offer an administrative opt-in profile. Retained internal dispatchers and chrome entries do not register tools or authorize access.
- Schemas describe model inputs, not all HTTP fields. Pi supplies project/session context and applies its existing redaction, cancellation, timeout, and error policy. Go still validates the received request.
- Optional fields preserve omission except documented Pi defaults; `false` and zero are not omission. Pi's `mem_context.max_bytes` and consolidation IDs use bounded integer schemas; batch confidence uses [0,1]. These schemas do not replace Go's validation.
- Pi renders HTTP data through a text result and `details.data`; MCP uses its tool-result text/project envelopes. Labels, status summaries, MCP annotations, descriptions, and defer-loading metadata are transport/presentation information, not authorization.

## Real-schema diagnostic

With Node.js 24, run `npm ci --ignore-scripts --legacy-peer-deps` in `plugin/pi`,
then `node tools/pi-schema-diagnostic.mjs` from the repository root (`--help` is
the only option). The fixed local test-only TypeBox dependency supplies actual
serialized registration schemas in a disposable sandbox; no Pi SDK is assumed.
The command reads `docs/contracts/agent-contract-v1.json`, never regenerates it.
Baseline freshness belongs to the separate Go generator check, not this diagnostic.

Completed diagnostics go to stdout with an explicit diagnostic-only/not-parity/
not-release-approval heading, a difference count and sorted tool/JSON-pointer paths.
Each line shows Go and Pi JSON values; `<missing>` marks absence. Inventory and
duplicate registration lines use `/registrations`; every duplicate schema is compared.
Object key order is ignored; arrays retain order. No constraint, host mapping or
known capability gap is allowlisted, including integer/number and required/optional
differences. Missing fields report their complete subtree, not an inferred equivalent.
This is literal structure, not semantic equivalence (even descriptions can differ).

Exit 0 means no structural differences or help, **never a parity certificate**;
exit 1 means differences (expected for current source); exit 2 means unsupported
arguments or unavailable/invalid baseline, real TypeBox, capture or cleanup.
Failures leave stdout empty and emit one fixed stderr line, without imported error
text/private paths. No partial report is emitted before cleanup completes. There
are no path/dependency overrides, network access, writes to source/dependencies,
capability changes or publication actions. Tests assert the diagnostic behavior;
they do not require current schemas to match. The rejection-only release checker
and candidate publisher safeguards remain independent and unchanged.

## Field audit

Fields listed below record the Pi input surface and its current MCP/HTTP differences. They do not assert identical schemas, defaults or response envelopes across transports. “Runtime-injected” means the host owns the value; it must not be recovered from a model-supplied session ID. “Transport-specific” describes a deliberately different adapter envelope. “Semantic” identifies a restriction or canonical-input choice. “Accidental loss” is an outstanding capability gap, not an approved design exemption.

| Tool | Pi fields | Projection reason / remaining difference |
| --- | --- | --- |
| `mem_search` | `query` (required); `type`, `project`, `scope`, `limit`, `all_projects`, `match_mode`, `response_format` | Query becomes HTTP `q`. Pi supplies its resolved project unless `all_projects=true`, which suppresses the project filter. Supplied `response_format` is forwarded unchanged; Go validates it and owns the compact `{ result, results }` projection with previews and relations. Omission preserves the legacy HTTP result array. **Transport-specific:** Pi renders the HTTP payload through its native text/details envelope rather than MCP's tool-result envelope. |
| `mem_search_prompts` | `query` (required); `project`, `all_projects`, `limit` | Query becomes HTTP `q` at `/prompts/search`. Omission supplies the resolved current project; explicit `all_projects=true` suppresses only the implicit project, preserving any explicit project so Go rejects conflicting selectors. Default limit is 10; nonpositive limits use the default. Full stored content and identifying context pass through unchanged. **Transport-specific:** MCP wraps `results` in its project envelope; Pi returns the HTTP array in text/details. Results are historical prompts, not proof of human authorship or current instructions. |
| `mem_save` | `title`, `content` (required); `type`, `scope`, `topic_key`, `project`, `cwd`, `capture_prompt` | **Runtime-injected:** confirmed effective `session_id` and available current prompt for the same session/project. Project/cwd resolution precedes saving; omitted Pi scope becomes `project` rather than relying on core omission defaults. **Semantic:** Pi requires canonical `content`; MCP also accepts the legacy `observation` alias. **Transport-specific:** MCP `project_choice_reason` / `recovery_token` belong to its ambiguous-project recovery protocol. Pi forwards `capture_prompt`; omission defaults to save-time capture, while `false` suppresses that save's attempt and current-prompt payload, not independent lifecycle capture. Go owns best-effort capture and deduplication. |
| `mem_update` | `id`, `expected_project` (required); `title`, `content`, `find`, `replace`, `type`, `scope`, `topic_key` | ID becomes the HTTP path; required `expected_project` becomes a query ownership assertion, also required by MCP and validated by Go. Supplied `find`/`replace` strings (including empty strings) go unchanged through existing redaction to PATCH. Omission stays omitted. Go owns pairing, conflict with supplied `content`, literal case-sensitive replace-all, no-ops, byte limits and mutation effects; Pi adds no validation or replay. |
| `mem_consolidate` | `ids_to_delete`, `new_title`, `new_content`, `expected_project` (required); `type`, `topic_key`, `confirm`, `fingerprint` | Shared canonical arguments and exact JSON-integer ID bound. Default preview performs no writes; only explicit confirmation with Go's opaque fingerprint may consolidate. Source project/session/scope overrides are refused by Go. **Transport-specific:** HTTP status/flat error/code/optional replacement plan become native error metadata; no client plan algorithm, auto-confirmation or uncertain-POST replay. |
| `mem_suggest_topic_key` | `type`, `title`, `content` | Shared fields go unchanged to `POST /topic-keys/suggest`. Go owns family prefixes, normalization and rejection of empty input. Pi returns Go's topic key; no JavaScript algorithm or invalid-input fallback remains. |
| `mem_save_prompt` | `content` (required); `project`, `cwd` | **Runtime-injected:** confirmed effective `session_id`. **Transport-specific:** MCP ambiguous-project `project_choice_reason` / `recovery_token` are not HTTP inputs. Pi's `prompt_id` / `status` result is projected from the HTTP receipt. |
| `mem_session_summary` | `content` (required); `project`, `cwd` | **Runtime-injected:** confirmed effective `session_id`. Pi writes a `session_summary` observation with host-owned title/type/scope. **Transport-specific:** MCP ambiguous-project `project_choice_reason` / `recovery_token` are not HTTP inputs. |
| `mem_session_finalize` | `summary` (required); `project`, `cwd` | **Runtime-injected:** exact confirmed current host effective session ID in the HTTP path and validated owner in the body; no model `session_id`, implicit registration, or arbitrary session selection. Optional project/cwd assert that owner, never route to a satellite. **Transport-specific:** HTTP requires explicit owner rather than copying MCP project-choice/recovery tokens. Go's local retry journal preserves original summary identity; Pi pins unknown delivery, blocks lifecycle reopening, and avoids substituting legacy end. No automatic POST replay. |
| `mem_context` | `project`, `scope`, `max_bytes`, `compact`, `older_history` | Pi defaults project to resolved context and forwards supplied bounds/format flags. Optional boolean `older_history` preserves explicit false and omission; Go defaults it to false and owns the bounded overview of counts/sampled titles outside the recent window. Existing project/scope filters and byte/compact formatting remain Go-owned; this is not observation-version pagination. HTTP malformed/empty boolean query values fall back to false, not a validation error; the model schema remains boolean. **Semantic validation projection:** Pi's `max_bytes` is a positive integer; MCP declares a number and Go validates the byte budget. Context and activity/nudge envelopes differ by transport. |
| `mem_get_observation` | `id` (required); `include_history`, `history_cursor` | Pi forwards supplied history controls to HTTP GET, including explicit `false` and `0`; omission preserves the bare ID request. Go validates the cursor and owns bounded history pages, truthful version counts and continuation metadata. Pi preserves results/errors without automatic paging; a cursor alone is ignored by Go unless history is enabled. **Transport-specific:** MCP's optional `project` chooses validated response context, not row ownership filtering; HTTP ID lookup does not add that envelope or row-visibility filtering. |
| `mem_session_start` | `id` (required); `directory` | **Runtime-injected defaults:** project is resolved by Pi; absent directory uses the detected directory or host cwd. The ID is a caller-provided registration input, not authority to replace Pi's runtime identity for subsequent writes. |
| `mem_session_end` | `id` (required); `summary` | **Semantic/runtime restriction:** only the current host ID is accepted; Pi maps it to its effective registered session and coordinates shutdown. MCP permits its own caller-session workflow. End independent/manual sessions through a separate client, not by overriding the Pi host ID. |
| `mem_current_project` | `cwd` | **Runtime projection:** Pi defaults `cwd` to host cwd because the HTTP server can run elsewhere. MCP accepts `directory` / `cwd` aliases; Pi exposes only `cwd`. The omitted alias is a schema difference, not identical input surfaces. Go owns project resolution. |
| `mem_doctor` | `check`, `project` | Shared selectors and HTTP diagnostics; Pi supplies resolved project when omitted. **Runtime/result projection:** Pi adds `caller_binding` from per-invocation host evidence; it does not register a session or mutate ownership to diagnose it. |
| `mem_capture_passive` | `content` (required); `source` | **Runtime-injected:** effective `session_id` and resolved project. Missing source becomes `pi-tool`; content is sent through the common redaction policy. MCP's model-visible `session_id` is deliberately absent from Pi. |
| `mem_review` | `action` (required); `project`, `limit`, `observation_id`, `id` | Shared action and ID alias. Pi lists globally when project is omitted (`all_projects=true`); mark-reviewed supplies the explicit or resolved project to the HTTP endpoint. Project-resolution failures remain errors, not implicit global writes. |
| `mem_judge` | `judgment_id`, `relation` (required); `reason`, `evidence`, `confidence`, `session_id` | Shared fields. Omitted provenance `session_id` falls back to the host ID; this existing provenance field is not the session-registration identity used by observation/prompt/summary/passive writes. |
| `mem_judge_many` | `judgments` (required, 1–32 objects with `judgment_id`/`relation`; optional `reason`, `evidence`, `confidence`); shared `session_id` | One HTTP POST; Go validates the batch before writes and returns ordered success/error outcomes with independent item transactions. Shared provenance replaces per-item provenance. Unlike legacy Pi `mem_judge`, omission stays empty as in MCP instead of injecting the host ID. HTTP errors/partial outcomes are preserved; no client loop, rollback, exactly-once claim or uncertain-POST replay. |
| `mem_compare` | `memory_id_a`, `memory_id_b`, `relation`, `confidence`, `reasoning` (required); `model` | Shared fields forwarded to HTTP. Required-field order has no semantic significance. |
| `mem_list_projects` | none | Shared empty input; Pi calls the HTTP project inventory, not MCP's text renderer. |
| `mem_pin` | `id` (required) | Shared ID; Pi maps it to HTTP PUT on the observation pin resource. |
| `mem_unpin` | `id` (required) | Shared ID; Pi maps it to HTTP DELETE on the observation pin resource. This removes a pin, not an observation. |

## Verification and remaining work

`plugin/pi/test/agent-profile.test.mjs` exercises actual extension registration, exact Go inventory equality, absence of administrative tools/hard-delete schemas, and retained executable/renderable agent tools. `topic-key-contract.test.mjs` exercises the registered tool's HTTP request, unchanged Go result, validation errors, and absence of observation/session writes. The isolated real-server test in `native-tool-contract.test.mjs` compares Pi against the real Go HTTP endpoint for family-prefixed, Unicode, content-fallback, and long-title inputs; rejected input leaves the initially empty observation inventory unchanged. Go's MCP topic-key tests pin the shared family-based example and validation.

`agent-workflows.test.mjs` covers registered consolidation preview/confirmation/drift metadata, single-request ordered batch outcomes and rejection, host-only finalization/explicit retry/unknown-outcome lifecycle guards, pre-dispatch cancellation and no ambiguous-POST replay. These are mocked transport checks, not proof of real-server integration. Go's public-route workflow tests cover store-backed ownership, no-change refusals, partial outcomes and retry identity; applicable package and independent verification are recorded separately for each candidate.

The existing project/session/privacy/timeout/error suites remain applicable. Passing inventory and topic-key checks alone does not establish their results or full contract parity.

The existing `search-compact.test.mjs` and `observation-history.test.mjs` regressions cover registered-tool optional-field forwarding, legacy omission behavior and preservation of Go responses/errors. Go's `TestSearchCompactHTTPContract` and `TestObservationHistoryHTTPInputs` cover the corresponding public routes. Their presence is not a passing result; execution evidence is recorded separately for the candidate.

`mem-update.test.mjs` covers mocked registered-tool schema/forwarding and real isolated Go HTTP behavior: exact pairing/conflict/input-bound errors, case-sensitive replace-all, Unicode, deletion, empty-find/no-match/identical no-ops, metadata with no-match, full-content updates, the 50,000-byte default boundary, and result-growth/empty-result errors. Complete public observation/history and stats snapshots protect rejection/no-op state; revision/history deltas protect successful updates. Admission rejection and the tested transactional failures preserve state, not every possible failure stage or uncertain delivery. Legacy-named tests provide deterministic public diagnostics for a separately executed base/candidate differential. This is #1981 evidence scope, not full parity or independent-review proof; candidate SHA, execution results and pending differential evidence belong in the delivery report.

Outstanding work includes the `mem_current_project.directory` alias projection. Per-save `capture_prompt`, compact search, observation-history controls and `mem_context.older_history` are already implemented; they are not outstanding capability gaps. The #1982 context regressions separate mocked forwarding from isolated real Go overview/filter/budget/read-only-state checks and source-only package guards; passing results and parent-owned differential proof are recorded separately for each candidate. Ambiguous-project recovery and ID-lookup project context remain transport differences, not fields to forward blindly. This audit does not claim full semantic parity or silently redesign those protocols.
